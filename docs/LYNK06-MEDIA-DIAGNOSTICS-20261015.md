# 原车仪表媒体诊断记录

诊断针对原车仪表自带音乐区域的 CarPlay 封面，以及原车媒体回调触发的播放、暂停和切歌。

## 自动记录

- 每次进入 CarPlay 媒体发送接口的请求分配进程内唯一编号，记录指令、来源、当时播放状态，以及请求时是否已处于目标状态。
- 同一编号记录发送任务排队耗时、HID 按下和释放各自的写入结果。事件通道缺失及写入异常有独立记录。
- 手机播放状态或歌曲信息变化时列出正在发送及已发送请求的候选编号。连续请求可能对应同一次变化，记录不将它当作手机对特定指令的确认。
- 请求五秒后记录观察窗口结果，区分排队、正在写入和已发送。排队超时的任务后来执行时仍保留实际排队耗时。
- 原车歌曲列表发布记录版本、iPhone 封面引用和图片短编号。HTTP 服务记录图片登记、每次请求的开始和结束、GET/HEAD、HTTP 状态、实际响应体字节数、异常类型及耗时。短编号在诊断报告脱敏后仍可区分。
- 仪表导航请求的开启与关闭单独记录，可按时间对齐封面发布和读取。
- 已有 READ_LOGS 权限时，会话期间订阅原车媒体/DIM 的指定 logcat 标签；保留原车事件时间、接收时间、封面短编号，并执行报告现有脱敏。采集每秒最多接收 60 行，报告包含采集状态、记录行数和限流丢弃数。权限不足或采集进程失败会留下明确记录。
- 会话关闭时结束未完成请求的跟踪并停止原车日志子进程；记录进入现有轮转日志及诊断报告。

HTTP 200 只表示响应写入完成；HID 写入成功只表示本地事件通道写入完成。手机状态变化与原车日志用于进一步判断后续行为，不能由这些结果直接推断仪表已经显示图片或手机确认执行指令。

## 验证范围

新增测试覆盖发送排队、按下/释放失败、多请求候选、状态早于写入完成、已处于目标状态、延迟执行、有界跟踪与关闭；封面测试核对 GET/HEAD 的响应体记录及脱敏后不同图片的关联；原车日志测试核对权限拒绝、脱敏关联、进程退出与关闭时终止读取。
